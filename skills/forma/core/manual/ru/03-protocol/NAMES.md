# Имена протокола

У каждого кода рядом есть человеческое имя; код — это адрес, имя едет вместе с ним (правило чата — skill `human-register`, «Names in the chat language»). Этот раздел — реестр имён: маршруты, надстройки, параграфы закона, запреты, именованные ключи. Ключи остаются английскими на любом языке; каждый язык мануала несёт свои имена в своём зеркале.

## Маршруты route-0…8

| Код | Ключ | Имя | Описание |
|---|---|---|---|
| `route-0` | `intent-self` | на ходу | `Intent` сам понимает, делает, записывает в карточку и принимает; для работы короче своей карточки — опечатка, одно значение, переименование по точному списку. Ни одного вызова — нет постоянной части расхода. |
| `route-1` | `intent-copy` | двойник | Копия `Intent` в чистом контексте исполняет по одной карточке, главный `Intent` принимает. Для большой задачи, которую лучше всех понимает `Intent`, — это `route-0` без засорения. |
| `route-2` | `intent-run` | поручение | `Intent` пишет карточку с критерием, `Run` исполняет в чистом контексте со стандартным снаряжением, `Intent` принимает по критерию. Для ТЗ в принятом документе, стандартного снаряжения и критерия, проверяемого фактом. |
| `route-3` | `intent-kit-human` | совет | `Intent` называет вопрос, `Kit` собирает основания и варианты, человек решает. Для выхода-вопроса, а не поставки: `Run` нечего исполнять. |
| `route-4` | `intent-kit-intent` | мастерская | После карточки от `Intent` `Kit` исполняет сам. Для оснастки движка, разведки незнакомого стека, подключения инструмента или доступа — работы, где знание арсенала и есть исполнение. |
| `route-5` | `intent-kit-run` | под заказ | `Kit` собирает снаряжение под задачу, `Run` исполняет, `Intent` принимает. Для ясного ТЗ, которому нужна роль, которой нет в стандартном снаряжении: особый скилл, доступ, MCP, внешний сервис. |
| `route-6` | `spec-run` | по образцу | `Spec` режет, снаряжение берётся по имени из библиотеки, `Run` исполняет, `Intent` принимает. Для вида задачи, который уже встречался; критерий пишет не принимающий. |
| `route-7` | `spec-kit-run` | полный ход | Полный круг: `Spec` режет и пишет критерий, `Kit` снаряжает, `Run` исполняет, `Intent` принимает — четыре разных контекста, каждый узел ловит свою потерю. Для дорогой или незаметной ошибки, нового стека, неочевидного критерия. |
| `route-8` | `segments-waves` | стройка | Масштабный конвейер: сегменты × волны из `route-2`…`route-7`, подготовка делится на сегмент, независимые задачи идут параллельно. Для большой цели, чей образ ясен и устойчив. |

## Надстройки over-1…4

| Код | Ключ | Имя | Меняет | Описание |
|---|---|---|---|---|
| `over-1` | `kit-library` | склад | снаряжение берётся готовым | Снаряжение не собирается, а берётся готовым по имени вида задачи; выгодна на повторяющемся виде. |
| `over-2` | `external-model` | подряд | исполнителя (внешняя дешёвая модель) | Исполнителя заменяет внешняя дешёвая модель; выгодна на механике с проверкой фактом — не там, где нужно суждение. |
| `over-3` | `series` | тираж | число исполнений на одну подготовку | Одна нарезка и одно снаряжение на N исполнений; постоянная часть подготовки делится на N — выгодна на однотипной серии. |
| `over-4` | `batch-accept` | партия | приёмка | Приёмка — одна на пакет; выгодна на потоке однородной мелочи с одним критерием на весь пакет. |

## Параграфы закона §1–7

| § | Ключ реестра | Имя | Описание |
|---|---|---|---|
| §1 | `law-1` | Пять пар | Пять узлов как одно тело: чем каждый судит круг, что решает о следующем и во что схлопывается, если пара ломается. |
| §2 | `law-2` | Маршрут | Путь от открытия цели до вердикта `Core`; таблица событий говорит, куда уходит каждый возврат. |
| §3 | `law-3` | Пороги | Два объявленных числа — попытки на задачу и карточки на круг; расход токенов и время — статистика, а не пороги. |
| §4 | `law-4` | Вешка | Маркер в первой строке каждой передачи и вопрос принимающего, привязанный к своей потере, до начала работы. |
| §5 | `law-5` | Запреты | Запреты, сформулированные утвердительно; каждый несёт имя и живёт в этом реестре. |
| §6 | `law-6` | Карточка и форма | Карточка как пять полей и четыре зоны; критерий готовности как машинные ворота и судимый вердикт; английские ключи; материалы карточки — внутри её папки. |
| §7 | `law-7` | Доска | Доска живёт в `.devtool/features/`; узел, берущий карточку, синхронизирует `status` и `assignee` через `card-move.cjs`. |

## Запреты 1–18

| № | Ключ реестра | Имя | Описание |
|---|---|---|---|
| 1 | `prohibition-1` | чужая приёмка | Работу подтверждает только принимающий узел — никогда не исполнитель, подтверждающий сам себя. |
| 2 | `prohibition-2` | точный адрес | Пробел называется точно — адресом и ожидаемым значением, — не растворяется в «непонятно». |
| 3 | `prohibition-3` | бюджет через стоп | Бюджет меняется только через стоп с отчётом и записью нового значения. |
| 4 | `prohibition-4` | свой порог | Каждый узел останавливается сам на своём пороге. |
| 5 | `prohibition-5` | журнал как есть | Провалы остаются в `JOURNAL.md` как есть; «Чего не хватало» заполняется каждый круг и не переписывается задним числом. |
| 6 | `prohibition-6` | пример — не мера | Пример показывает возможную форму; требуемое определяют только критерий готовности и спецификация. |
| 7 | `prohibition-7` | чистая карточка | Исполнитель получает чистую карточку и снаряжение — без истории собственных прошлых провалов. |
| 8 | `prohibition-8` | цель под замком | `GOAL.md` и версии справочников не меняются, пока человек не подтвердит достижение цели; переоткрыть достигнутую цель может только человек. |
| 9 | `prohibition-9` | кэш неизменного | Кэш круга несёт только неизменное — переменное в него не входит. |
| 10 | `prohibition-10` | возврат меняет снаряжение | Возврат задачи меняет хотя бы одну из шести единиц снаряжения. |
| 11 | `prohibition-11` | указание — в запись | Указание человека вне маршрута записывается как изменение — оно никогда не остаётся незаписанным. |
| 12 | `prohibition-12` | чужой дефект — назад | Дефект вне собственной работы уходит назад по таблице маршрута — не чинится на месте. |
| 13 | `prohibition-13` | адрес и ожидание | Расхождение называется обоими — адресом и ожидаемым значением; одно без другого недостаточно. |
| 14 | `prohibition-14` | второй диагноз — стоп | Второй одинаковый диагноз подряд — это стоп, а не ещё одна пересборка. |
| 15 | `prohibition-15` | ключ в одном доме | Доступы живут по виду ровно в одном месте; карточка называет доступ и его статус, но не значение. |
| 16 | `prohibition-16` | чистые зоны | Файлы, поставляемые в другие проекты, не несут следов проекта; история живёт в карточках, `.forma/living/` и `JOURNAL.md`. |
| 17 | `prohibition-17` | выход через скраб | Наружу к внешней модели или сервису уходит только прошедшее скрипт очистки; отказ — закрытый отказ. |
| 18 | `prohibition-18` | коммит по-английски | Сообщения коммитов репозитория протокола — только английские; репозиторий проекта держит свой язык. |

## Именованные ключи

| Ключ | en | ru |
|---|---|---|
| `Plumb` | Plumb | отвес |

Отвес — имя проекта для меры соответствия роли между нарезкой и исполнением (`PLUMB.md`); en-зеркало этого реестра несёт имя Plumb.

## Где живёт имя

- чат — skill `human-register`, «Names in the chat language»;
- машинный словарь — `.forma/i18n/keys.json` (`routeNames` для маршрутов и надстроек, `lawSections` для параграфов закона, `prohibitionNames` для запретов, `namedKeys` для именованных ключей);
- параграфы закона и запреты — этот реестр.
