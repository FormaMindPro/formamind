# LANGUAGE - языковой слой движка

Как движок говорит с человеком: режимы речи, политика словаря, скелеты отчётов. Машинная сторона - `.forma/i18n/registers.json`; этот файл - правило для человека. Язык проекта называет собственный конфиг проекта (`PROJECT.md`, «Язык проекта»); эта пара (`manual/en/` - оригинал, `manual/ru/` - точная копия) на него не переводится.

## Режимы речи

Два полюса - качества двух узлов (`AGENTS.md` §1):

| Режим | Как звучит | Когда |
|---|---|---|
| твёрдый | сначала коды и факты: «Критерий допускает два прочтения: A или B?» | работа, расход, маршруты, протокол, продукт |
| мягкий | тот же факт плюс состояние, человеческими словами: «Здесь страшно ошибиться: A или B?» | интервью, предложения баланса, собственная проверка человека |

Факт, адрес и причина одинаковы в обоих режимах - меняется только обёртка. Мягкость, сдвинувшая факт, - подмена.

## Карта

`.forma/i18n/registers.json` связывает каждый код эпика из `PROJECT.md` («Эпики проекта») с режимом, несёт человеческое имя эпика на объявленных языках (ru-имя обязано совпадать с ячейкой конфига), политику словаря и скелеты отчётов. Человек переносит режим в другой полюс правкой карты - ни один скилл её не перекрывает. `check-register` (`.forma/board/checks/`) роняет код эпика без режима, ключ без человеческого имени на объявленном языке и ru-имя, разошедшееся с конфигом.

## Политика словаря

Ключи всегда английские, каков бы ни был язык проекта (`AGENTS.md` §6); метки - только запас для документов без якорей. В речи с человеком функциональный ключ несёт своё человеческое имя на языке чата, адрес рядом с ним (запрет 20). Реестр имён - `.forma/i18n/keys.json` и manual `NAMES.md`.

## Скелеты отчётов

Отчёт движка (шаг, передача): что изменилось, по артефактам; выводы гейтов с кодами выхода; открытые риски с адресом и ожидаемым значением. Отчёт проекта (человеку): что человек теперь видит; куда смотреть, ссылки; что ждёт решения человека. Скелеты лежат в `reportSkeleton` карты; режим красит формулировки, никогда - секции.

## Скилл: human-register

`human-register` (`.forma/skills/human-register/SKILL.md`) превращает карту в поведение: перед речью говорящий читает режим текущего эпика и объявляет его. Скилл читает только `Intent` - никакая другая роль его не носит. Установщик по умолчанию кладёт копию в каждый адаптер реестра; карта доставки - `.forma/verify/skill-delivery.json`:

| Адаптер | Доставка | Состояние |
|---|---|---|
| claude | `.claude/skills/human-register/` | установленная копия |
| qoder | `.qoder/skills/human-register/` | установленная копия (зона есть, движок спит) |
| zcode, gemini | `.forma/skills/human-register/` | движково-нейтральный канон, читается нативно |
| codex, minimax | объявленный путь | зоны нет - только объявление, без файлов |

`check-skill-delivery` (`.forma/verify/`) роняет адаптер реестра без объявленной доставки, установленную зону с отсутствующей или разошедшейся с каноном копией, файлы скилла в зоне без установленной папки и роль, читающую скилл не `Intent`.

## Предупреждение о голых кодах

Stop-хук (`.claude/hooks/stop-names.cjs`) предупреждает, когда финальное сообщение несёт голый код - адрес без человеческого имени рядом (запрет 20). Это напоминание, не проверка: предотправный скан остаётся за говорящим. Движки, чьи события хуков не имеют стоп-аналога (gemini, qoder, zcode), провода не получают; предотправный скан остаётся за ними.
