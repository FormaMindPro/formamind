# Локализация дашборда

Дашборд говорит на двух языках: английский (по умолчанию) и русский. Переводится только интерфейс; содержимое проекта остаётся на языке проекта.

## Что переводится

- Всё, что рисует сам дашборд: вкладки, подписи, кнопки, подсказки, пустые состояния, счётчики, названия статусов и этапов.
- Строки, которые сервер отдаёт ключом или кодом с параметрами, — их переводит браузер.

## Что не переводится

- Заголовки и тела карточек, тексты проверок, названия разделов из файлов `project/`, вопросы интервью, описания файлов в виде «Структура».
- Консольный вывод сервера и сообщения CLI.
- Сообщения об ошибках API: английские.

## Словари

`.forma/dashboard/locales/en.json` и `ru.json` — по одному плоскому объекту на язык, ключи одни и те же.

- `{name}` — подстановка; формы числа — `one`, `few`, `many`, `other`.
- Запас — английский; ключ, найденный нигде, показывается как есть.
- Новый язык — новый файл `locales/<код>.json`.

## В коде

- В браузере: `t('ключ', {vars})`, `cnt('ключ', n)`; в разметке — `data-i18n`, `data-i18n-ph`, `data-i18n-title`.
- Таблицы подписей — функции или геттеры, не константы: язык меняется без перезагрузки.
- Кириллица в коде, которая есть данные, а не интерфейс (имя поля карточки для сверки с текстом, родное имя языка), несёт метку `i18n-keep` в своей строке.

## Ключи протокола

Ядро английское: заголовки зон, вид карточки, ключи снаряжения, глаголы истории и ключи `PROJECT.md` — английские слова одного словаря `.forma/i18n/keys.json` (ключ → английский и русский лейблы). Язык — только локализация: лейблы словаря и тексты после ключа. Код читает поля по ключу, а не по русскому написанию (`.forma/i18n/key-language.test.cjs`); карточку с неанглийским ключом показывает проверка доски `key-language`, исправляет `node .forma/board/migrate-keys.cjs --apply`.

## Проверка

`locale-parity` идёт вместе со сверкой движка (`sync-engines --check`):

- в обоих словарях одни и те же ключи;
- каждый ключ из кода и разметки есть в словарях;
- в словарях нет неиспользуемых ключей (динамические покрывает префикс);
- в `web/` нет кириллицы вне комментариев и строк с `i18n-keep`.

Тест `.forma/dashboard/locale-parity.test.cjs` доказывает, что проверка краснеет на каждом виде поломки и зелёная на чистом коде.

## Локализация каркаса проекта при установке

При установке проекта (`forma init`) ядро проверяет наличие готовых эталонных пакетов каркаса в `templates/_scaffold/<code>` (по умолчанию поставляются `en` и `ru`).

- **Поддерживаемый язык (`en`, `ru`):** сразу разворачивается готовый эталонный каркас соответствующей локализации. Файл `.forma/translation-pending.json` не создаётся, проект готов к работе без лишних вызовов моделей.
- **Новый/пользовательский язык (`de`, `fr`, `es` и др.):** инсталлятор разворачивает базовый английский каркас `templates/_scaffold/en/`, фиксирует выбранный язык в `PROJECT.md` и создаёт маркер `.forma/translation-pending.json`. Агент переводит файлы каркаса по шагу «Skeleton translation» скилла `forma`.
- **Масштабирование на новые языки:** после создания и проверки качественного перевода для нового языка каталог с переведёнными файлами может быть добавлен в дистрибутив протокола как `templates/_scaffold/<код>/`.

## Проверка и тесты паритета (scaffold-parity)

Для всех встроенных пакетов каркаса гарантируется строгий структурный паритет:
- Тест `test/scaffold-parity.test.cjs` проверяет идентичность набора файлов между `en` и остальными пакетами;
- Для всех markdown-файлов проверяется равенство количества и уровней заголовков `#` и `##` (`skeletonOf`), а также совпадение и порядок машинных якорей `<!-- k:... -->`.

## Утилита синхронизации скаффолдов (scaffold-sync)

Для предотвращения рассинхронизации между английским эталоном и локализованными пакетами (`templates/_scaffold/<lang>`) протокол содержит утилиту `scripts/scaffold-sync.cjs`:

```bash
# Проверить паритет по всем доступным языковым пакетам
node scripts/scaffold-sync.cjs --check

# Проверить конкретный язык
node scripts/scaffold-sync.cjs --lang ru

# Машиночитаемый JSON-отчет
node scripts/scaffold-sync.cjs --json
```

Утилита проверяет:
1. Недостающие или лишние файлы в целевом пакете;
2. Сохранение машинных якорей (`<!-- k:... -->`);
3. Иерархию и количество заголовков (`#` ... `####`);
4. Структуру ключей в шаблонах JSON (`resources.rules.json`).
