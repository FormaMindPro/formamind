# Живая картина интервью — контракт файла

Вкладка «Интервью» дашборда строится по файлу `project/brief/picture.json`. `Intent` пишет файл по ходу интервью по брифу; дашборд только читает его — и редактирует ровно одно поле, `status` догадки, по клику человека.

**Нет файла — нет идущего интервью.** Это не ошибка и не пустая заглушка: вкладка прямо сообщает об этом. Сломанный JSON показывается отдельно от отсутствующего, потому что это разные вещи — во втором случае разговора нет, в первом он идёт, но картина повреждена.

**Кто пишет и когда.** Картина перерисовывается **по отправленным раундам ответов**, а не после каждой фразы. `Intent` целиком перезаписывает файл раз за раунд и увеличивает `round`.

**Машинные имена остаются каноническими.** Имена пяти позиций, ключи слоёв (`человек` / `предмет`) и остальные ключи ниже — машинный словарь файла: они пишутся в точности как здесь, независимо от языка проекта. Свободный текст (`text`, `label`, `tag`, `topic`) следует языку проекта.

---

## Форма файла

```jsonc
{
  "topic": "интервью по брифу проекта",
  "round": 2,                       // номер последнего отправленного раунда
  "updated": "2031-01-01T12:00:00+00:00",   // реальный ISO таймштамп с таймзоной
  "finished": null,                 // ISO, когда интервью закрыто

  "positions": [                    // пять позиций сценария (project/brief/interview.md)
    {
      "name": "Облик",              // строго одно из пяти имён, см. ниже
      "state": "answered",          // пишется только "answered" или "now";
                                    // available/blocked/ready вычисляются, не хранятся
      "fill": 100,                  // 0-100; опционально, 100 по умолчанию для answered
      "text": "Описание внешнего вида: ключевые сценарии, аудитория…",
      "layers": {                   // только для позиций 3 и 4
        "человек": { "text": "…" },
        "предмет": { "text": "…" }
      },
      "guess": {                    // опционально — догадка для этой позиции
        "id": "g-pos2",             // уникален внутри файла; клик приходит по нему
        "text": "Догадка архитектора, выведенная из ответов человека.",
        "status": "open"            // open | confirmed | rejected
      }
    }
  ],

  "tree": {                         // предметное дерево; null, пока не отвечена первая позиция
    "id": "n-root",
    "label": "Мой проект",
    "role": "root",                 // root | part | fn — чем узел является для дерева
    "kind": "said",                 // said | guess | pending
    "tag": "project",               // подпись справа от имени; догадка ставит свою
    "from": "position 1",           // откуда взялся узел: "position N" или "round N"
    "fresh": false,                 // появился в последнем раунде — подсвечивается
    "status": "open",               // только для kind: "guess"
    "children": []
  }
}
```

## Вопросы: первый проход открытый

**Агент придумывает варианты выбора.** Опросник с готовыми вариантами на первом проходе зафиксировал бы в брифе идею агента, одобренную человеком, вместо идеи человека, записанной агентом — и незаметно обошёл бы главное решение этой картины, потому что формально всё «сказано человеком: он кликнул».

Отсюда: **первый проход по позиции — открытый** — поле для слов человека, без вариантов выбора. Варианты появляются со второго прохода и строятся **из того, что уже сказано** — чтобы уточнить, разбить, завершить. Так опросник тратит усилия на разворачивание мысли, а не на подсовывание самой мысли.

**Разговор идёт на странице интервью** — скилл `forma-grill-with-ui`, отдельная вкладка, открываемая по кнопке позиции. Внутри дашборда формы сознательно нет: два места ввода ответов на одни и те же вопросы утомляют больше, чем один привычный формат, к которому человек привыкает. Дашборд показывает, страница спрашивает.

**Три слоя, и их нельзя путать.** Страница интервью — это транспорт (`events.jsonl` сессии). `project/brief/answers.jsonl` — дословная запись сказанного, внутри брифа, потому что запись разговора принадлежит проекту, а не папке сессии скилла, которая когда-нибудь будет вычищена. `picture.json` — это синтез `Intent`.

**Ответы человека хранятся дословно и отдельно** — `project/brief/answers.jsonl`, одна строка на отправку. Картина (`picture.json`) — это их синтез узлом `Intent`. Два файла, а не один, именно потому, что «сказанное человеком» и «понятое агентом» не должны лежать в одном месте под одним именем.

## Стартовый раунд позиции 1 «Облик»

Три вопроса, независимых друг от друга: они идут одним раундом, на них можно отвечать в любом порядке и по одному.

| | Вопрос | Что вытягивает |
|---|---|---|
| **1** | Проект уже работает. Вы показываете его человеку, который о нём ничего не знает — открываете и даёте посмотреть. Что он видит перед собой? | Картину, которая и так есть в голове, вместо определения. Из неё выпадают объекты — заготовки для предметного дерева |
| **2** | Назовите одну-две существующие вещи, на которые это похоже. И сразу — чем ваше от них отличается | Сравнение с существующим, которого прямо требует `interview.md`. Назвать существующее почти ничего не стоит; «чем отличается» вытягивает то, ради чего проект делается. Идёт в `brief/reference.md` |
| **3** | Что в нём должно первым бросаться в глаза? А что, наоборот, должно быть незаметным, уходить вглубь? | Иерархию, а не список: что главное, что вспомогательное. Мостик ко второй позиции — здесь уже проглядывают части |

**Чего в первом вопросе сознательно нет.**

«О чём ваш проект?» — вопрос, на который почти невозможно ответить плохо и почти невозможно ответить полезно: он вытягивает миссию, тогда как позиция 1 требует узнаваемого облика, чего-то, на что можно показать пальцем.

«Что человек почувствует в первые пять секунд?» — это человеческий слой **позиции 3**. Заданный первым, он дал бы ответ о пользе, облик остался бы неназванным, и третья позиция затем спросила бы то, на что уже отвечено — и что хуже, без частей.

Мы не спрашиваем имя человека: обращение по имени не делает ответ лучше, а первый вопрос слишком дорог, чтобы тратить его на анкету. Имя войдёт в строку «Дата · кто говорил» записи интервью, когда понадобится.

**Раунды остальных позиций пишутся, когда до них доходит черёд**, вместе с человеком — не сочиняются заранее. Вопрос, составленный до того, как услышан предыдущий ответ, спрашивает о воображаемом проекте.

## Порядок: фронтир, а не список

Позиции открываются не по очереди, а по мере готовности предпосылок. Первая и вторая доступны сразу — облик и членение, ни одна не ждёт другую. Третья ждёт вторую: вопрос «какую общую цель части выполняют вместе» без названных частей заставляет человека догадываться за то, чего он не сказал. Четвёртая ждёт третью.

Состояние позиции **нигде не хранится** — оно вычисляется из ответов и зависимостей при каждой сборке. Вторая запись о нём разошлась бы с первой.

| Состояние | Что значит |
|---|---|
| `available` | предпосылки созрели, можно отвечать |
| `blocked` | ждёт названную позицию; видно и подписано, чего именно ждёт |
| `now` | человек отвечает прямо сейчас |
| `answered` | ответ записан |
| `ready` | только пятая: первые четыре закрыты, проверка не проведена |

**Закрытая позиция не прячется.** Скрытая читалась бы как несуществующая, тогда как серая с надписью «ждёт позицию 2» говорит и о порядке, и о том, что впереди.

## Два слоя для позиций 3 и 4

Человеческий слой — что чувствует адресат; предметный слой — какая функциональность это производит. Одно без другого вырождается: чувство без функциональности — обещание, функциональность без чувства — работа на неизвестную цель.

В файле это `layers` у позиции: `{ "человек": { "text": "…" }, "предмет": { "text": "…" } }`. Позиция закрыта, когда закрыты оба слоя. Для разговора это означает, что проходов не пять, а семь, и каждый меньше — ради чего деление и затевалось.

## Пятая позиция — не вопрос к человеку

`Маршрут` помечен `asks: "intent"`, и у него нет кнопки «ответить». Маршрут — это разведка узла: ветка задаётся полем «Шаблон проекта» в `PROJECT.md`, и при готовом шаблоне `Intent` **проверяет** записанное в `ROUTE.md`, а не сочиняет его заново. Кнопка звала бы человека делать работу узла.

Человек принимает или оспаривает результат проверки — теми же ✓ и ✗, что и догадки.

## Имена на экране — со стороны предмета

`Облик`, `Части`, `Общая цель частей`, `Внутренняя функциональность`, `Маршрут`. Внутренние названия качеств — Красота, Простота, Индивидуальность, Честность, Естественность — на экран не выносятся: вопрос не должен объявлять, какое качество он вытягивает, иначе человек начинает отвечать на категорию, а не о своём проекте.

---

**Позиция, которой нет в файле, рисуется пустой, а не выбрасывается:** пять позиций — это всегда пять, иначе не видно, о чём ещё не спросили.

**`kind: "pending"`** — это ветка-заглушка «функции ждут позицию 4». Не догадка: у неё нет автора и нет содержания, в ней нечего подтверждать.

---

## Три состояния знания

Главное решение здесь, и оно не про верстку: **то, что человек сказал, то, о чём агент догадался, и то, что никому не известно, показываются по-разному, и третье не выдаётся за второе.**

| В файле | На экране | Что значит |
|---|---|---|
| `kind: "said"` | сплошной контур | человек сказал это прямо |
| `kind: "guess"`, `status: "open"` | пунктир, плашка «уточняется» | агент вывел из слов; спрашивается в следующем раунде, здесь не решается |
| `kind: "guess"`, `status: "confirmed"` | — | не используется: человек сказал это в интервью, значит это `said` |
| `kind: "guess"`, `status: "rejected"` | — | не используется: отклонённое не попадает в картину |
| `kind: "pending"` | пунктир, серый | об этом ещё не спрашивали |

**Догадка помечается поузлово, а не областью** (Q4·C). Без этого она незаметно становится решением человека: он увидит её на экране, она покажется знакомой, и он не станет спорить. Прототип v1 показал ровно это — убедительно нарисовал четыре части, хотя человек о них не говорил.

---

## Где решается неясное

Догадка — это не объект, требующий решения, а **знак того, что интервью не закончено**. Видя, что что-то не понято, `Intent` задаёт следующий раунд и спрашивает до тех пор, пока человек не ответит полно и ясно. Доска показывает **результат**, а не список нерешённого.

Следствия:

- догадки не должны накапливаться в `picture.json`: то, что ещё неясно, — это вопрос к следующему раунду, а не узел с плашкой;
- узел, ещё не согласованный, помечается «уточняется». Это **информация, а не предложение решить**: у неё нет кнопок;
- с доски есть переход в интервью — «Открыть интервью». Единственное действие, которое доска предлагает по поводу неясного — пойти и спросить.

**Почему прежнее правило было отменено.** Клик по догадке выглядел дёшево — одно движение вместо разговора. Но он закрывал вопрос, **не задавая его**: человек соглашался с формулировкой агента вместо того, чтобы сказать своими словами. Разница видна на первом примере — «чай» вместо признанного «Отчаянного»: подтверждённая кликом, эта догадка осталась бы моим прочтением под их подписью, а не их словом.

---

## Чем заканчивается

К закрытию интервью догадок остаться не должно: для этого и нужны раунды — каждая становится вопросом и получает ответ. То, что всё же осталось невыясненным, уходит в **запись «пока не уточнено» рядом с брифом** — не в сам бриф и не в `ROUTE.md` (Q6·C, Q7·B).

Не в бриф, потому что бриф — опорная точка и не переписывается на ходу: предположение, осевшее в нём, через месяц читается как слово человека, и **глаз перестаёт видеть плашку**. Не в `ROUTE.md`, потому что там живёт туман по маршруту, тогда как здесь — по предмету, и пришлось бы через раз читать с вопросом «о чём это».

Отклонённое не идёт никуда: человек уже посмотрел на это и сказал «нет».
