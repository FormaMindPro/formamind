# CONFIG — конфигурация структуры проекта

Об устройстве конкретно этого проекта — какие каталоги, какие файлы, за что каждый отвечает; растёт вместе с целями, как и `PROJECT.md`. Не путать со справочником `manual/` в корне проекта — тот универсален, не о проекте, и не меняется.

Девять разделов: по два на каждый «рабочий» узел (роль + формируемая документация) и один центральный для `Core` — таблица ниже. Документация `Kit` (раздел 6) шире, чем журнал оснастки: она несёт всю структуру проекта, пофайлово и покаталожно, с сутью каждого.

---

## Девять разделов (по узлам)

Принцип организации — по узлам: пара разделов на каждый из четырёх «рабочих» узлов (роль + формируемая узлом документация) и один центральный раздел `Core` вне пар. 4×2 + 1 = 9.

| № | Узел | Раздел | Суть | Где |
|---|---|---|---|---|
| 1 | `Intent` | Интервью | сбор брифа — что человек сказал до первой цели, не переписывается на ходу | `project/brief/interview.md`, `history.md`, `reference.md` |
| 2 | `Intent` | Приёмка и сопровождение | проверка каждой задачи и круга на критерий, приёмка отчётов `Run`, ведение проекта в разговоре с человеком — `Intent` как единая точка входа для человека | распределено намеренно: `GOAL.md` (история проверок), `ROADMAP.md` (что дала цель), `JOURNAL.md` (факты круга) — три файла с разными типами записей |
| 3 | `Spec` | Нарезка | деление круга на связанные карточки задач | `.devtool/features/` (карточка наверху), `spec.md` |
| 4 | `Spec` | Статистика и ценность | что нарезано и что получено в итоге — цена/расход, из чего состоит продукт, для наглядности | `project/ops/VALUE.md` — заводится `Spec`, вызывается `Intent` при закрытии цели (`intent-cycle-closing.md`, «После вердикта») |
| 5 | `Kit` | Работа и роль | комплект задачи: доступ, данные, навык, инструмент, модель | `kit.md` |
| 6 | `Kit` | Документация (оснастка) | вся структура проекта (что за файл/каталог, его суть) + журнал: какой инструмент/доступ/скилл появился и какую брешь закрыл | этот файл → раздел «6. Kit — Документация (оснастка)» ниже |
| 7 | `Run` | Работа и роль | исполнение в точности порученного по выданным скиллам, без отсебятины | `run.md` |
| 8 | `Run` | Документация (по проекту) | чистовое описание сделанного, по карточкам вида «дело», для человека | `project/docs/` (по целям, `docs/goal-NN-<name>/`) |
| 9 | `Core` | Центр | вердикт кругу в целом (не сумма пяти проверок), пороги, диагноз узлам, тренд равновесия | `core.md`, `GOAL.md` → «Итог серии», `JOURNAL.md` |

## 6. Kit — Документация (оснастка)

Этот раздел несёт не только журнал оснастки, но и всю структуру проекта — `Kit` знает структуру в точности для того, чтобы снаряжать. Карта структуры и журнал оснастки — одно знание, один раздел.

### Технические контракты среды

Ограничения среды, которые `Kit` обязан закладывать в комплект заранее. `PROJECT.md` держит лишь имя инструмента и ссылку на якорь здесь.

#### Контракт `omitClaudeMd` {#omit-claude-md}

Факт: субагент по умолчанию получает полный `CLAUDE.md`, если это явно не выключено полем `omitClaudeMd: true`.

### Журнал оснастки

Справка по собственной оснастке системы: какой инструмент, доступ или скилл появился и какую брешь закрыл. Не хронология — хронология в истории каждой карточки; здесь только вывод, годный для будущего.

**Пишется узлом `Kit`, в порядке хозяйства, при закрытии каждой цели** (`kit.md`, «Конфиг»; вызывается `Intent`, `intent-cycle-closing.md`, «После вердикта»). Источник — карточки эпика «3. Протокол проекта» о своём (ресурс/инструмент/скилл), закрытые с прошлой сводки.

**Читается узлом `Kit` при снаряжении**, перед внешними источниками готового (скилл `skill-authoring`, «Источники готового»): брешь уже могла быть закрыта в прошлой цели.

#### Шаблон записи

```
### <инструмент/доступ/скилл> — цель N, круг M

**Закрыл брешь:** <что не работало или чего не хватало>
**Карточка-источник:** `.devtool/features/done/<файл>.md`
```

---

Пока записей нет — первая появится при закрытии первой цели.
